## ⚠️ 关键教训：Bash 工具 inline `python -c` 的反斜杠会被多层转义污染
- 本轮多次踩坑：`r'\\\\left'` 经 bash 双引号处理后匹配层数错乱，导致「第一轮修复」把 2936 个正确 `\frac` 计数进去（实际是模式被降级成了单反斜杠匹配），且产生了 `\$\underline` 这种污染数据。
- **规则：凡涉及反斜杠/正则/JSON 转义的 exam.json 修改与验证，必须写 .py 脚本文件执行，禁止 inline python -c。**
- **规则：改 exam.json 前先 git 状态干净（可随时 git checkout 还原）；每轮修改后用独立 .py 全量验证（双转义残留、$ 包裹规范性）。**
- 中间损坏版本可能被用户浏览器 SW 缓存——数据修复必须走 commit + CACHE_VER bump + push 闭环，不要指望本地热改生效。
