## CACHE_VER 未触发更新缺陷（重要工程教训）
- 现象：改了 `pwa/js/exam.js` 但 pre-commit 报 `CACHE_VER 未变`。实测 HEAD~1 实际资源哈希 `806676e364`，当前（含新 exam.js）哈希 `e315ef7bde`，而 HEAD/HEAD~1 的 sw.js 都记录 `e315ef7bde` → 版本号超前于仓库内容。
- 成因：**按指定路径部分提交** + 钩子按**工作区全量**算哈希 → sw.js 版本号可能反映未提交状态；后续真变化哈希可能恰好等于已发布值 → SW 不换缓存 → 用户看不到改动。
- 修复 `tools/build_sw.py`：① `--bump` 强制升版（`-uN` 后缀）；② 后缀保留（常规运行不回退 `-uN`→纯哈希）；③ pre-commit 自动检测（`git diff --cached HEAD` 有 PRECACHE 改动且哈希同 HEAD 值 → 自动 `-u1`）；④ 替换正则须吃掉原分号（否则 `'...';;`）。
- **判断版本号是否真会更新**：比较 `git show HEAD:pwa/sw.js` 的值与"用户端已加载值"是否相同，不能只看 build_sw 报"未变"。必要时 `python tools/build_sw.py --bump`。
