# 2026-09-06 工作日志

## 真题页笔记图片竞态修复（commit 02f7293，已 push，CACHE_VER=mathcards-5459acfb31）

### 症状
1. 手动保存（💾 保存 / 完成 / 顶部保存）图片存不上，必须等自动保存跑完后再存才成功。
2. 点「✏️ 编辑」进入编辑态时**偶尔**丢图片（更严重：永久丢）。

### 根因
- **手动保存竞态**：贴图后 blob 异步压缩(1200px JPEG)几百 ms 才写 IndexedDB。手动保存不等待写库完成就落盘 + 渲染只读预览 → `fillExamNoteImgs` 取不到 blob → 300ms 重试仍失败 → `replaceWith('[图片已丢失]')`。若自动保存(1.5s 防抖)已把 `_noteLastRendered[qid]` 记为同文本，写库完成后的 `renderNotePreview` 因内容去重直接 return，预览永久停在「图片已丢失」。
- **点编辑丢图**：`toggleNoteEdit` 进入编辑时 `noteToEditor` 从 localStorage 文本重建编辑器 DOM（新 img 节点），随后 `fillExamNoteImgs(ta)` 回填若偶发失败（IDB 事务刚开/竞争）→ replaceWith 编辑器里的 img 节点。编辑器 DOM 是数据载体——节点被换成文本后保存序列化丢 `[图:id]` → `noteInput` 孤图清理（orphan）删 IDB blob → **图片永久丢失**。

### 修复（exam.js + exam.css）
1. 新增 `_pendingImgTasks`（id→写库 Promise）+ `waitPendingImgs()`；`saveNoteBtn` / `toggleNoteEdit` 完成分支 / `saveNoteFromOps` 三条手动保存路径改为 async，**await 所有贴图写库完成后再落盘/收起/渲染预览**（提示「图片保存中…」）。
2. `fillExamNoteImgs` 两处防御：
   - `_pendingImgTasks[id]` 命中（写库中）→ 不标丢失，等写库完成后再回填该 img；
   - **编辑态**（同卡编辑器 `display!=='none'`，即编辑器 DOM 或编辑态预览）取不到 blob → 保留节点+令牌，仅标 `.img-fail` 斜纹占位 + title「保存不会丢失」；只读态才允许 replaceWith('[图片已丢失]')（数据在文本，替换仅影响显示）。
3. `renderNotePreview` 加只读态守卫（`ta.style.display==='none'` 直接 return），避免写库完成回调把已渲染好的只读预览覆盖成编辑态（带删除×）样式。

### 教训（重要，已并入 MEMORY.md）
- **contenteditable 编辑器 DOM 是笔记数据载体**：回填图片失败绝不能 replaceWith 文本——替换 = 序列化丢令牌 → 孤图清理删 blob → 永久丢。失败时保留节点（img-fail 占位），数据靠 DOM 里的 `[图:id]` 令牌兜底。
- annotate.js 架构不同（图片令牌载体是编辑器下方缩略图卡片条，不在编辑器 DOM），同类替换仅影响显示，无需同步修。
- category.js 无贴图编辑竞态，未改。
