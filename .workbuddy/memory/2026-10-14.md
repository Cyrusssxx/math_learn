## 随机选题拼卷 —— 需求梳理（grill-me，尚未实现）

### 已敲定的 9 项决策（实现时照此）
1. **抽样**：**加权随机**（无放回）——不会 5 / 不熟 3 / 只收藏无状态 1 / **已掌握 0（完全排除）**
2. **池子边界**：**严格只从收藏抽**；某题型不够就**缩水**并在卷首诚实标注（不跨题型、不放宽到未收藏）
3. **卷面**：**像 exam.html**（左栏 + 主区 + 悬浮题号导航），**加计时器**
4. **历史拼卷**：左栏列表（「MM-DD HH:mm · N题」），每项 × 删整卷，**保留最近 10 份**，存 localStorage
5. **计时器**：**180 分钟**，可暂停/继续/重置，到时**只提醒不强制**
6. **分值**：**统一 150 分制** —— 选择 5×10=50、填空 5×6=30、解答前 4 题 12 分+后 2 题 11 分=70
7. **卷首**：显示状态构成（不会 N · 不熟 N · 无标记 N｜选择/填空/解答各几题）
8. **章节**：**轻约束** —— 抽完检查「至少覆盖 5 章」，不满足重抽（上限 20 次，试不出就接受）
9. 题型配额：**选择 10 / 填空 6 / 解答 6 = 22 题**（2024–2026 数二真题结构）

### 关键实现
- `PP_SHAPE`：选择 10×5 / 填空 6×5 / 解答 4×12+2×11 = 22 题 150 分

- `ppKindOf(secTitle, q)`：**题型只信 `section.title`**（含「选择/填空/解答」），`q.kind` 只作兜底

## 每日做题数据（掌握地图置顶）2026-10-14

用户要：「category 要记录每天打标记的数量也就是做题的数据，放在掌握地图置顶」。

### 实现
- **记录模块放在 `common.js`**（被全部 8 个页面加载）：
  `markDaily(qid, kind)` / `dailyRecent(n)` / `dailyStreak()` / `dayKeyOf()`
- **存储**：`localStorage 'dailyMarks' = { 'YYYY-MM-DD': { qid: kind } }`，保留最近 120 天
  - kind ∈ `unknown` / `unfamiliar` / `cleared` / `fav` / `unfav`
  - **计数口径 = 当天做过的题数**（按 qid 去重，同一天同一题只占 1 条）
- **写入点**：`toggleStatus` / `toggleFav` —— **三处副本都要加**（category.js / exam.js / exam-shared.js）
- **展示**：`mastery.js` 的 `mmDailyCard()` 插到 `body.innerHTML = mmDailyCard() + bars + groupsHtml`
  即掌握地图**置顶**：今日题数 + 类型细分 chips + 🔥连续天数 + 近 14 天柱状图 + 近 14 天总题数

### ⚠️ 最大的坑：**绝不能在 statusSave/favSave 里拦截**
那两函数各有 **9 处调用**，其中 **4 处是数据迁移**（migrateXdLegacyKeys / migrateLinkFixKeys /
migrateAliasKeys / migrateOrphanNote）。在里面记账会把「标记搬家」全部误记成「今天做了 47 题」。
→ 必须只在**用户主动操作路径**（toggleStatus / toggleFav）调用。
→ 已写**反向验证**测试：用真实标注数据加载页面（触发 47 项迁移）后 `dailyMarks` 必须为空 ✓

### 边界处理
- `dayKeyOf` 用**本地时区**手拼 YYYY-MM-DD（**不能用 `toISOString()`** —— 那是 UTC，晚上会差一天）
- 连续天数：今天还没做**不算断签**（从昨天继续数）
- 取消标记也算「动过这道题」（值记 `cleared`，仍是 1 条）

## 拼卷：加入「收藏时间优先」+ 章节覆盖取最多（2026-10-14）

用户要：抽题时优先收藏时间**较早**的题，越早优先级越高；并「尽量确保题型类多」。

### 实现
- **权重改成两层相乘**：`w = sw × tf`
  - `sw` = 状态权重（不会 5 / 不熟 3 / 仅收藏 1）——**原字段 `w` 改名为 `sw`**，`w` 现在是最终权重
  - `tf` = **池内收藏时间排名**系数 `1 + 2×(1−rank)`（rank 0=最早 → tf=3；rank 1=最近 → tf=1）
  - 用**池内相对排名**而非绝对天数：池子变大/变小都不会让系数失衡
  - 设计意图：早收藏的「仅收藏题」(1×3=3) 仍低于近期「不会」(5×1=5)，**状态优先级不被推翻**
- **章节覆盖**：把原来「够 5 章就早停」改成 **20 次重抽里取覆盖最多的一版**（用户要"尽量广"）。
  实测从 9~11 章提到 **10~12 章**。`PP_MIN_CH` 常量随之删除。

### ⚠️ 测试设计的重要教训：必须**控制变量**
首版断言写成「早半区在卷中的占比 > 50%」→ 实测 **46.4%**（看着像功能没生效）。
**真因**：你近期标的「不会」更多（sw=5），把时间权重整体压住了 —— **整体占比会被状态分布掩盖**。
改成**同状态内比较**才有效：
- 同状态（仅收藏）内：早的占 **58.5%**（池中 50%）✓
- 同状态（不会）内：早的占 **55.0%**（该组仅 71 道、且时间分布集中 → 偏移被稀释）✓
- 权重层面（确定性）：早半平均 tf **2.52** vs 近半 **1.50** ✓
→ 教训：**验证"某因子生效"时，必须先控制其它因子的分布**，否则会得出反向结论。

### 数据前提（已核实）
收藏 301 条**全部有时间戳**，跨度 **45.6 天**（2026-08-25 → 10-10），28 天有收藏、每天 2~34 条。
若将来有时间戳缺失的收藏，`tf` 兜底为 1（不偏袒）。

测试 `_chk_paper.js` 增至 **52 项**（新增 A3 段：tf 单调性/极值/两端占用、同状态两组端到端、
章节覆盖 ≥5），runner **23 项全绿**。

## 全量导出/导入 —— 设备迁移（2026-10-14）

用户要：「继续检测有哪里导出不了的，我要全量导出和导入，方便更换设备刷题」。

### 盘点结果（导出的完整清单）
- **localStorage 全量**（不做白名单）—— 键名散落 10+ 文件且大量动态拼（examNote-<qid>、
  selFav-<id>、selNote-<id>…），白名单必漏。同源下 localStorage 只有本 app 数据，全量最稳 ✓
- **IndexedDB 只有 2 个库、都是贴图**：`notesAnnotImg`（标注贴图）、`examNoteImg`（做题笔记贴图），
  值是 Blob → 导出时 FileReader 转 **dataURL**；导入时 fetch(dataURL) 转 Blob 写回。
- 记忆卡 SRS 状态、好题收藏、精选收藏、阅读时长都在 localStorage 里，全量导出自然覆盖 ✓

### 实现（common.js，index 主站入口）
- **导出** `exportAllData()`（async）：localStorage 全量 + `idbDump(两个库)` → 一个 JSON
  （`做题数据-YYYY-MM-DD.json`，v2），alert 显示统计摘要与文件大小
- **导入** `importAllData(file)`：确认弹窗（列出将覆盖的数据量）→ localStorage.clear() 恢复
  → idbRestore 两个贴图库（**清空式**，覆盖旧图）→ 提示刷新
- **入口**：index 左栏底部「导出数据 / 导入数据」（与「导出标注」同组）
- ⚠️ idbDump/idbRestore 都加**超时兜底**（dump 3s/4s、restore 500ms）——
  stub/异常环境下 tx.oncomplete 可能不触发，会把导出永久挂起（实测踩过）

### 测试踩坑（4 个，全是 jsdom 的坑）
1. **jsdom 的 Blob 没有 `text()`** → 用 FileReader.readAsText 读
2. **jsdom 的 `location.reload` 不可 redefine**，且真调它会抛 Navigation 错 → 不 mock，
   断言用 alert 代替；测试尾部立即 process.exit 避开 600ms 后的 reload
3. **stub 的 tx.oncomplete 有时不触发**（setTimeout(8) 不执行，而 setTimeout(0) 能）→
   产品代码加兜底 + 测试塞图改同步写
4. **fakeFile 要补 `text()` 方法**（importAllData 读文件用）

### 测试 `_chk_export2.js` 19 项
- A：localStorage 零遗漏（281 键）、贴图 dataURL、摘要数字
- **B（核心承诺）**：**换设备往返** —— 导出 → 新空白环境（塞了不同的旧数据+旧图）→ 导入 →
  **281 键全部一致** + 贴图恢复成 Blob + 旧图被清 ✓
- C：防御（非法 JSON / 非本站文件 / 用户取消 / 没选文件 → 全部不动数据）
