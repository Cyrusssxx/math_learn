## 真题笔记图片保持原始比例与尺寸，不再强制拉伸铺满（八十八节，commit `dacfbbf`）
- 用户反馈：真题练习界面插入笔记图片后被强制拉伸铺满整个笔记框；要求保持图片原始比例和尺寸，仅当用户手动调整时才改变大小。
- 根因定位：`pwa/css/exam.css` **四处强制尺寸**叠加（无 JS 参与，纯 CSS 问题）：
  1. `.exam-note-img { width:100% }` —— 显示态图片被撑到笔记框满宽（**主因**，小图被放大、大图被压缩）；
  2. `.exam-note-img-wrap { width:100% }` —— 外层容器强制铺满；
  3. `.q-note .q-note-input[contenteditable] img.exam-note-img { max-height:260px }` —— 编辑态强制压高；
  4. `.q-note-input .exam-note-img-wrap { width:160px; max-width:45% }` —— 编辑态内联图被固定 160px 宽。
- 改法：四处统一改为「**原始尺寸优先 + 仅超宽时等比缩**」：
  1. `.exam-note-img`：`width:100%`→`width:auto`，新增 `max-width:100%`，保留 `height:auto`（按原始宽度显示、保持宽高比、小图不放大、超宽才等比缩防溢出）；
  2. `.exam-note-img-wrap`：`width:100%`→`width:fit-content` + `max-width:100%`（容器收缩到图片实际宽度 → hover 删除按钮「×」贴合图片右上角，不再是容器右边缘）；
  3. 编辑态 img：去掉 `max-height:260px`；
  4. 编辑态 wrap：`width:160px`→`width:auto`、`max-width:45%`→`100%`。
- 关键认知：手动调整写入的 **inline `style` 优先级高于 class 规则**，因此用户手动设定的尺寸不会被这些 CSS 默认值覆盖回原样。

## 批注贴图丢失（切题丢图）根因与修复 ✅ 已 push (`dda94e4`, CACHE_VER→`mathcards-e440ed9187`)
- **现象**：用户报「批注里打空格不显示」「手动保存不生效、要等自动保存」「插入多张图片还是可能丢失」「搞下一道题上一道的图就没了」——核心是**切笔记/保存时整条批注的图片从 IndexedDB 被清空**。
- **根因（致命）**：`onPasteImg` 只在 `imgPut(...).then()` **异步回调**里才把缩略图卡片塞进 `.ann-imgs` 条，而 `annEditorToNote` 从这条抓 `[图:id]` 令牌。若「粘贴后立刻点保存」早于异步写入完成（或切题瞬间触发保存），`text` 抓不到令牌 → `saveNote` 里 `imgDel(refsOf(prev).filter(id=>!kept.includes(id)))` 因 `kept` 为空 → **把该条批注此前所有图片 blob 从 `notesAnnotImg` 库全删**（一次保存清空整条，故「特别多」）。
- **次因（编辑态缩略图空白）**：`annThumbCard` 生成的 `<img>` 缺 `ann-img` 类，而 `fillImgs` 只匹配 `img.ann-img[data-img]` → 编辑框缩略图永不回填 blob，显白块（显示态 `.ann-text` 因 `renderAnnot` 自带 `ann-img` 类能正常显示）。
- **修复**（`pwa/js/annotate.js`，commit `dda94e4`）：① `onPasteImg` **同步**先把缩略图卡片登记进条（令牌即时可见），`imgPut().then()` 仅负责回填该卡片 blob（此时必已落库、不误判丢失），写库失败则摘占位卡片；② `annThumbCard` 的 img 补 `class="ann-img"` 让 `fillImgs` 能回填；③ `saveNote` 双保险：`if(!ed) return`（非编辑态不执行、防误清空整条）+ `kept` 取 `refsOf(text) ∪ annStripIds(ed)`，即使令牌意外丢失仍以条内实际卡片为准、绝不误删。

## 批注「清除格式」补齐第三步 ✅ 已 push (`7453788`, CACHE_VER→`mathcards-70d2e904da`)
- **需求**：用户「注意这里批注的正文 我要的是清除格式吧」——批注工具条上那个按钮原本叫「正文」，title 承诺「去掉标题/字色/高亮」，但实现只有两步：`formatBlock→P`(清 H1/H2) + `removeFormat`(清粗斜)，**缺第三步剥高亮/字色**。
- **根因**：批注高亮在编辑器里是 `<mark style="background:...">`（`annNoteToEditor` 由 `<h:#xxx>` 令牌生成），字色是 `span[style*=color]`/`<font color>`；`removeFormat` **清不掉 background(-color) 内联样式、拆不掉 `<mark>`**。正是 408-quiz 复用文档点名的坑：「`clearNoteFormat` 三步缺一不可，否则清除格式不生效」。
- **修复**（`pwa/js/annotate.js`）：① 新增 `annStripFormat(ed)`——清 `background/background-color/color` 内联样式、去 `<font bgcolor/color>` 属性、**拆 `<mark>` 只留文字**（仅处理选区覆盖节点，无有效 range 时处理整个编辑框）；② `annApplyFormat` 的 `plain` 分支调用它，并在**无选区（仅光标）时先全选**再三步清除（即"清除整条批注"）；③ 改完 DOM 后补 `annPreviewOnInput(ed)` 同步实时预览；④ 按钮文案「正文」→「清除格式」，title 同步。
- **实测**（agent-browser，本地 8765）：塞入 `<h1>+<b>+<mark background>+span color+<i>` → `applyFmt('plain')` → 清除后 `marks/h1/b/i` 全为 0，HTML 变 `<p>大标题<br>粗体高亮红字斜体</p>`；保存后落盘 `"大标题\n粗体高亮红字斜体"`，**格式令牌剩余 0**（`<h:>/<c:>/<b>/<i>/<h1>` 全无）。
- **复用教训**：contenteditable 的"清除格式"必须三步——`formatBlock→P` 清块级、`removeFormat` 清行内、**手动遍历剥 background/color 并拆高亮容器**；`removeFormat` 对 `background-color` 无效这条要记住（408-quiz 文档已验证，math-note 踩了同一个）。
