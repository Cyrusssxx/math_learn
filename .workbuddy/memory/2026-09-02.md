## 真题笔记图片保持原始比例与尺寸，不再强制拉伸铺满（八十八节，commit `dacfbbf`）
- 用户反馈：真题练习界面插入笔记图片后被强制拉伸铺满整个笔记框；要求保持图片原始比例和尺寸，仅当用户手动调整时才改变大小。
- 根因定位：`pwa/css/exam.css` **四处强制尺寸**叠加（无 JS 参与，纯 CSS 问题）：
  1. `.exam-note-img { width:100% }` —— 显示态图片被撑到笔记框满宽（**主因**，小图被放大、大图被压缩）；
  2. `.exam-note-img-wrap { width:100% }` —— 外层容器强制铺满；
  3. `.q-note .q-note-input[contenteditable] img.exam-note-img { max-height:260px }` —— 编辑态强制压高；
  4. `.q-note-input .exam-note-img-wrap { width:160px; max-width:45% }` —— 编辑态内联图被固定 160px 宽。
- 改法：四处统一改为「**原始尺寸优先 + 仅超宽时等比缩**」：
  1. `.exam-note-img`：`width:100%`→`width:auto`，新增 `max-width:100%`，保留 `height:auto`（按原始宽度显示、保持宽高比、小图不放大、超宽才等比缩防溢出）；
  2. `.exam-note-img-wrap`：`width:100%`→`width:fit-content` + `max-width:100%`（容器收缩到图片实际宽度 → hover 删除按钮「×」贴合图片右上角，不再是容器右边缘）；
  3. 编辑态 img：去掉 `max-height:260px`；
  4. 编辑态 wrap：`width:160px`→`width:auto`、`max-width:45%`→`100%`。
- 关键认知：手动调整写入的 **inline `style` 优先级高于 class 规则**，因此用户手动设定的尺寸不会被这些 CSS 默认值覆盖回原样。
- 影响面（自动跨页同步）：`category.html` / `selected.html` / `selected_ans.html` **同样加载 `exam.css`** → 分类页、精选页、精选答案页的笔记图片同步受益，无需另改 CSS；`index.html`(notes.css)、`good.html`(good.css) 不加载 exam.css，未受影响。
- 交付：commit `dacfbbf`（`pwa/css/exam.css` + pre-commit 钩子 bump `pwa/sw.js`），`CACHE_VER→mathcards-e48ce139fc`，已 push origin/main，远程 HEAD 一致。需 Ctrl+Shift+R 强刷。
- **遗留待办（未做，需用户确认后再动）**：「手动调整大小」当前**没有可用入口**且**调整后不持久化**：
  - 原因一：编辑器内 img 为 `contenteditable="false"`（exam.js `noteImgNode`），Chrome 原生缩放手柄对不可编辑元素不显示；
  - 原因二：`editorToNote` 只把图片序列化为 `[图:id]`，**不保存 style 尺寸** → 即便手动改了，保存刷新后尺寸丢失。
  - 可行方案（均**不动 `[图:id]` 令牌格式**，向后兼容、无需数据迁移）：
    - **A**：img 改 `contenteditable=true` 启用原生手柄 + `MutationObserver` 捕获 style 变化 → 按图片 id 存宽度到 `localStorage['examNoteImgW-<id>']`，渲染/回填时应用；exam.js 与 category.js 共享该尺寸。
    - **B**：自绘右下角拖拽手柄（`mousedown/mousemove/mouseup`，等比锁宽高比），跨浏览器表现一致、不破坏 contenteditable 语义 + 同样存 localStorage。
  - 两方案均只需改 exam.js（+ CSS 加手柄样式），不动序列化格式，风险可控；属中等改动，按用户「大改动先给完整计划」的约定，先交付核心修复并征询确认。
- **用户决定（2026-09-02）**：「不用搞这个」——**不做**手动调整图片大小功能，方案 A / B 均不实施。
  - 最终形态＝笔记图片保持原始比例与尺寸（小图不放大、超宽才等比缩），**无手动缩放入口、无尺寸持久化**，即 commit `dacfbbf` 交付的状态即为终态。
  - 后续不要再主动提议该功能；若用户日后另行提出，再按上述 A/B 方案评估。
