## ⚠️ 重大教训（本次血泪，务必记住）
1. **python 源码字符串转义陷阱**：`\a`、`\b`、`\f`、`\n`、`\r`、`\t`、`\v`、`\0` 是**合法 python 转义**！写 LaTeX 时 `<$` 后的 LaTeX 命令在 python 单引号字符串里：`$\arctan$` → `\a` 变 BEL(0x07)+`rctan`；`$\alpha$` 同理变 BEL。**LaTeX 命令一律写双反斜杠 `\\arctan`**。`\l`、`\f`、`\s` 等虽非法但保留字面（仅 SyntaxWarning，安全）。
2. **绝不对 exam.json 做基于'子串'的全库字节替换**：`'rctan'→'\\arctan'` 会误伤原文里所有 `\arctan`（文本层单反斜杠含 rctan 子串），连 `\\arctan`（JSON 双反斜杠）都中招 → 全库 179 处损坏、JSON 带控制字符非法。数据修复必须走 json.loads→定位题→dict 替换→json.dumps。
3. **re.sub 的 repl 会二次转义**：`re.sub(r'rctan', '\\\\arctan', a)` repl 中 `\a` 会再转成 BEL——用 `str.replace` 或 lambda。
4. **break 缩进陷阱**：多层 for 里 break 对齐错会把多 section 的批改只做到第一个 section（修复不落地）。写批量脚本用函数化/列表推导避免。
5. 修复污染步骤（已验证）：`git checkout -- pwa/data/exam.json` 恢复上次合法 commit → 修生成脚本转义 → 重跑 → 严格校验（python `json.loads` 严格模式 + BEL 计数 + KaTeX）。
